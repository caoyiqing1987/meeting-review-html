# 🎬 Meeting Review HTML

把会议逐字稿 + 视频变成深色杂志风工作清单 HTML。一键生成，零外部依赖。

> 你开了一个会，录了视频，腾讯会议自动生成了逐字稿。然后呢？回看太慢、翻聊天记录太乱、发摘要给团队又不够细。
>
> 这个工具把逐字稿里的每一句讨论变成结构化工作卡片——有时间戳、有帧画面、有分类标签、有待办表格。一个单文件 HTML，发群里大家都能看。

## 输出长什么样

生成一个 `.html` 文件，打开就是：

```
┌─────────────────────────────────────┐
│  项目名称 · 工作清单                  │
│  YYYY-MM-DD · 时长 35:24 · 参与人    │
├─────────────────────────────────────┤
│ 📋 会议总结                          │
│ 核心议题摘要...                       │
│ [修改要求×6] [分镜要求×4] [技术×2]   │
├─────────────────────────────────────┤
│ C1  修改要求                          │
│ 画面构图调整，演员位置关系...          │
│ 「shenxin(00:19:34): 这个伞肯定再低」 │
│ [帧画面 560×315 点击可放大]           │
│ ⚠ 系统推测，请自行确认                │
├─────────────────────────────────────┤
│ C2  分镜要求                          │
│ ...                                  │
├─────────────────────────────────────┤
│ 📌 待办事项                          │
```

所有图片 base64 内嵌，单文件，可离线打开，可直接发微信/钉钉/邮件。

## 使用方法

### 第一步：准备好输入文件

```
你的项目目录/
├── video.mp4          ← 会议录像
├── transcript.txt     ← 逐字稿（腾讯会议导出或任何带时间戳的文本）
└── generate_review_html.py  ← 本仓库的脚本
```

### 第二步：提取视频信息

```bash
# 1. 看视频多长
ffprobe -v error -show_entries format=duration -of default=noprint_wrappers=1:nokey=1 video.mp4

# 2. 提取帧画面（每3秒一张）
mkdir -p frames
ffmpeg -i video.mp4 -vf "fps=1/3" -q:v 2 frames/frame_%04d.jpg
```

### 第三步：阅读逐字稿，提取工作项

打开 `transcript.txt`，逐段找出讨论要点。每个工作项包含：

- **镜头号/编号**（如 C1、D1、A1）
- **类型**：根据会议性质选分类（见下方）
- **标题**：一句话概括
- **详细描述**：通顺中文总结
- **原文引用**：逐字稿里原话完整引用
- **时间范围**：该段讨论的起止时间 → 换算成帧号

帧号计算公式：`帧号 = 时间秒数 / 3 + 1`

### 第四步：编辑脚本配置

打开 `generate_review_html.py`，修改顶部配置区域：

```python
PROJECT_NAME = "项目名称"
MEETING_DATE = "YYYY-MM-DD"
VIDEO_DURATION = "MM:SS"
PARTICIPANTS = "参与人A / 参与人B / 参与人C"
```

然后填充 `WORK_ITEMS` 列表：

```python
WORK_ITEMS = [
    {
        "id": "C1",
        "type": "修改要求",
        "title": "画面构图调整，演员位置关系改对",
        "summary": "客户反馈伞的位置太高，需要降低。同时法斗和柯基两个人要靠近一点，增加亲密感。",
        "quote": "「shenxin(00:19:34): 首先把画面的构图，演员位置关系改对。这个伞肯定再低一点…法斗柯基这两个人要近一点」",
        "frame_start": 392,
        "frame_end": 420,
    },
]
```

### 第五步：生成 HTML

```bash
python3 generate_review_html.py
```

输出 `meeting-review.html`，可直接用浏览器打开，或发到群里。

## 工作项类型分类

### 审片会（逐镜头审阅画面、提修改意见）

| 类型 | 含义 | 颜色 |
|------|------|:----:|
| 分镜要求 | 镜头结构、运镜、构图、叙事节奏 | 青色 |
| 修改要求 | 对已有画面的具体修改指示 | 红色 |
| 技术难点 | AI/特效实现困难，需要权衡 | 黄色 |
| 风格要求 | 整体视觉风格、影调、色彩方向 | 紫色 |

### 产品讨论会

| 类型 | 含义 | 颜色 |
|------|------|:----:|
| 产品决策 | 确定的产品方向、功能取舍 | 紫色 |
| 技术方案 | 技术选型、架构设计、API对接 | 青色 |
| 市场判断 | 行业趋势、竞争分析、定价 | 黄色 |
| 行动项 | 明确分工、待推进事项 | 红色 |

### 进度同步会

| 类型 | 含义 | 颜色 |
|------|------|:----:|
| 进度确认 | 已完成/进行中的工作确认 | 青色 |
| 问题 | 阻塞项、依赖未到位、bug | 红色 |
| 待办 | 下一步要推进的具体任务 | 黄色 |
| 风险 | 延期/质量/资源风险 | 红色 |

### 通用（混合型会议）

| 类型 | 含义 | 颜色 |
|------|------|:----:|
| 决策 | 已达成一致的结论 | 紫色 |
| 讨论 | 有分歧待定的议题 | 黄色 |
| 行动项 | 明确分配给某人的任务 | 红色 |
| 技术 | 技术方案/实现细节 | 青色 |

---

## 自定义

脚本顶部的 `TYPE_COLORS` 字典可以随时扩展。颜色语义保持一致即可——红色=要行动，青色=技术，黄色=风险/待议，紫色=方向/决策。

底部 `TODO_ITEMS` 生成待办表格。脚本`CONFIGURATION`区域的品牌角标文字也可以改成你自己的。
